# OlConnect — клиент olcRTC для Android

Клиент виртуального туннеля для Android 8.0 и новее (minSdk 26). Поднимает системный
`VpnService`, забирает IP-трафик в TUN и отправляет его через «белые» сервисы, которые
блокировщики не трогают: облачные редакторы документов, доски, конференции. Снаружи это
выглядит как работа с документом или встречей, внутри — L3-туннель.

Текущая версия — 1.7.68 (versionCode 182). Приложение ставится из APK-релизов GitHub,
в магазинах не публикуется.

## Как это работает

Трафик приложения перехватывается `VpnService` и попадает в TUN-интерфейс. Дальше есть три
пути:

1. **OpenFlux** — L3-туннель поверх облачных сервисов. Пакеты кодируются и уходят в
   обычные HTTPS/WebSocket-запросы к редактору документов, доске или комнате встречи.
   Поддерживаются несколько носителей (см. таблицу ниже); конкретный выбирается полем
   профиля или автоопределением по ссылке.
2. **OlConnect** — инкапсуляция в сессию видеоконференции (WebRTC): транспорт
   `vp8channel` для WB Stream и Телемоста, `datachannel` для Jitsi.
3. **Стандартные протоколы** — VLESS (TCP/raw, WebSocket, gRPC, XHTTP; TLS, REALITY,
   Vision flow), VMess, Trojan, Shadowsocks. Ядро — Xray, который поднимается внутри
   приложения вместе с собственным HEV-туннелем и SOCKS-петлёй.

Опционально включается сквозное шифрование полезной нагрузки (AES-256-GCM, ключ задаётся
в профиле или в ссылке `&k=`); для Яндекс Досок ключ обязателен на обеих сторонах.
DNS уходит в туннель; при включённом UDP-релее UDP-пакеты идут через носитель, иначе
возвращается ICMP Port Unreachable, и приложение само уходит в TCP.

## Поддерживаемые носители

Цифры — замеры на живом стенде, не синтетика. «Резерв» означает: код рабочий, но скорость
не даёт использовать канал как основной.

| Носитель | Значение транспорта | Статус | Цифры и особенности |
|---|---|---|---|
| Яндекс Доски | `boards` | Работает, самый быстрый канал | 1 МБ за 1,56 с (641 КБ/с), 10 МБ — 694 КБ/с, на 60 с — 952 КБ/с, отказов записи `refused=0`. Нужен ключ шифрования с обеих сторон |
| Cups (cups.online) | `cupsonline` | Работает, оптимум — 8 комнат | На v1.0.63 выход 10 МБ за 136 с (71,8 КБ/с); до исправления кадрирования было 11 КБ/с с полной остановкой на 40–45 с |
| Яндекс Документы (Волга) | `vyandex` | Работает, закрыт как резерв | 5–7 КБ/с |
| Яндекс Документы (классический) | `yandex` | Работает, резерв | Скорость ниже Волги; используется как запасной путь |
| Mail.ru Документы | `mailru` | Работает, закрыт как резерв | 6–8 КБ/с |
| Яндекс Телемост (OpenFlux) | `telemost` | Закрыт | Внешний потолок сервиса, не наша сторона |
| WB Stream | `wbstream` + `vp8channel` | Есть в коде, не в фокусе | Отдельно не замерялся |
| Jitsi | `jitsi` + `datachannel` | Есть в коде, не в фокусе | Отдельно не замерялся |
| Битрикс24 | `bitrix24` | Есть в коде | Отдельно не замерялся |
| Авито | `avito` | Не работает | Сломано на стороне сервиса |
| MAX / OneMe | `oneme` | Не реализовано | Нужны `maxToken` и `maxUid`; в ядре есть заготовка, в клиенте выбора нет |
| Автоопределение | `auto` | Работает | Носитель выбирается по ссылке на документ, доску или встречу |

## Возможности приложения

- **Профили.** Локальные профили всех поддерживаемых типов, редактор с проверкой полей,
  копирование ссылки профиля, удаление, избранное.
- **Импорт.** QR-код (камера или изображение из галереи), вставка из буфера, deep links
  (`olconnect://`, `olcrtc://`, `openflux://`, `vless://`, `vmess://`, `trojan://`, `ss://`),
  файлы конфигураций.
- **Подписки и зеркала.** Ссылка на подписку сервера Olcrtc_manager, автообновление,
  ручное обновление, зашифрованное зеркало (AES-256-GCM), если основной адрес недоступен.
- **Автопереключение.** При включённом тумблере служба перебирает профили в порядке
  «избранные → последний успешный → остальные», а не долбит один заблокированный канал.
- **Маршрутизация.** Пресеты «весь трафик через VPN» и «Россия напрямую», выбор приложений
  (все, все кроме выбранных, только выбранные), пользовательские правила по домену,
  суффиксу, IP, CIDR и пакету с действиями «через VPN», «напрямую», «блокировать».
- **DNS.** Свой сервер (по умолчанию 77.88.8.8:53, внутри туннеля — 1.1.1.1:53), запросы
  идут через туннель.
- **UDP.** Опциональный UDP-релей через носитель; без него заблокированный UDP честно
  отвечает ICMP, и приложение переходит на TCP без таймаутов.
- **Оформление.** Пять палитр (системная Material You, нейтральная, бронза, чёрная, моно),
  шесть вариантов акцента (авто, бирюза, синий, фиолетовый, роза, янтарь), интенсивность
  свечения, выбор фонового эффекта, отключение движения. Настройки применяются сразу и
  сохраняются между запусками.
- **Статистика.** Текущая сессия, суммы за сегодня и месяц, история подключений с
  причинами отключения.
- **Диагностика.** Журнал приложения (файл + logcat под тегом `olcrtc`, с редакцией
  секретов), экспорт отчёта, сетевые проверки.
- **Капча Яндекса.** Если ядро требует интерактивную капчу, клиент открывает встроенный
  экран с WebView поверх экрана подключения, забирает куки и сам перезапускает подключение.
- **Обновления.** Проверка релизов GitHub, скачивание APK через туннель или напрямую,
  проверка SHA-256 и отпечатка сертификата подписи.

## Сборка и релизы

Сборка и тесты — **только через GitHub Actions**. Локальные Gradle-, Android-, lint- и
APK-сборки запрещены правилами репозитория: нативная часть (Go + NDK) и подпись
воспроизводятся на раннере.

- `CI` — тесты Go-ядра и JVM-тесты приложения (в том числе тесты без устройства).
- `Security` — проверка секретов и лицензий зависимостей.
- `Release APK` — сборка по тегу `vX.Y.Z`, публикация релиза и артефактов.

В релиз входят три APK — `arm64-v8a`, `armeabi-v7a`, `universal` — плюс `SHA256SUMS.txt`
и отпечаток сертификата подписи (`SIGNING_CERT_SHA256.txt`). Установка обновления поверх
предыдущей версии проверяет совпадение отпечатка.

Политика версий: патч растёт до 9, затем минор (1.0.9 → 1.1.0). Сводное описание
изменений и единый релиз — на странице
[Releases](https://github.com/Oleglog/OlConnect/releases/latest).

## Что не работает и почему

- **Авито** — сервис изменил поведение на своей стороне, носитель отключён как вариант.
- **MAX / OneMe** — не хватает обязательных параметров (`maxToken`, `maxUid`), реализация
  не начиналась.
- **Телемост (OpenFlux)** — закрыт: потолок самого сервиса, клиентская оптимизация не
  помогает.
- **Яндекс Документы и Mail.ru** — рабочие, но медленные (5–8 КБ/с); оставлены резервом.
- **Тесты обновления клиента** (два случая) исключены из JVM-прогона: им нужен реальный
  JSON из Android SDK, на устройстве они проходят.

## Известные проблемы

- [#5](https://github.com/Oleglog/OlConnect/issues/5) — фильтр по владельцу соединения
  пропускает исключённые приложения через `tun0`: при `INVALID_UID` решение принимается в
  пользу пропуска.
- [#3](https://github.com/Oleglog/OlConnect/issues/3) — как сообщить о проблеме
  безопасности приватно. Пока канал не подтверждён, действует `SECURITY.md`.

## Связь трёх репозиториев

- **Клиент** — этот репозиторий: Android-приложение (Kotlin, Views + XML, Material 3) и
  вендоренная копия ядра в `native/mobilecore`.
- **Ядро и панель** — [`Oleglog/Olcrtc_manager`](https://github.com/Oleglog/Olcrtc_manager):
  транспортный рантайм, панель управления, серверные контракты подписок и зеркал. Клиент
  подключает его как Go-модуль через `replace` в `native/mobilecore/go.mod`; пин фиксируется
  в CI и проверяется на свежесть и происхождение.
- **Выходной узел** — `OpenFlux-Android`: вторая сторона туннеля, оттуда в клиент
  переносятся измерения и исправления носителей («mirror of exit» в истории коммитов).

## Экспериментальное

Эксперимент с оформлением «Рейка» (новая визуальная система: палитры, типографика,
рейка сессии) в основной код не вошёл и откатан в 1.7.68. Живёт в ветке
`experimental/design-rail-2026-11`, макеты — в отдельном каталоге `ofx-design`; в главной
ветке его нет.
